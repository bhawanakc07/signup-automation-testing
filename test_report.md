# Signup Automation - Test Report

**Site:** https://authorized-partner.vercel.app  
**Run at:** 2026-11-17, about 09:21 (Nepal time, UTC+05:45)  
**Tool:** Playwright (Python), Chromium, macOS

## Result: FAIL (blocked by the server)

1 of 6 steps passed. The run stopped at **"1. Set up account (with phone number)"**.

**Reason:** after the account form was sent, the site's backend answered with HTTP 429:

```
POST https://stage.cloudedu.com.au/api/tempuser/
429  {"detail": "Too many requests. Please try again later."}
```

The server asks the client to wait 1440 minutes (about 24 hours). The next attempt is possible after
**2026-11-18 09:21**. This is a server-side rate limit on the signup endpoint, not a problem in the
form filling. The script detected the 429, stopped at once, saved a screenshot and wrote this report.

## What happened in the run

1. The register page opened and the Terms checkbox was ticked. Continue opened the account form (PASS).
2. The script filled first name, last name, email, password, confirm password and a valid generated phone number.
   The site accepted the phone number (no validation error).
3. The script clicked Next once. The site's own server answered `200` (`/register?step=setup`), then the
   backend answered `429`.
4. Because the server asked for a wait of 24 hours, the script stopped instead of waiting.

## Earlier attempt (previous day)

On the previous day's attempt the site accepted the account form, sent the verification code to the email
inbox, and the flow reached the Agency Details page. The script then failed on that page. The script was
fixed afterwards for locked (pre-filled) fields and a pre-selected region. That fix has not yet been
confirmed on the live site because of the 24-hour rate limit.

## Observations for the site team

- The signup endpoint rate limit is reached after a few attempts; a QA/test account or whitelist is needed
  for automated testing.
- The page shows no visible message when the 429 happens; the user only sees that nothing happens.
- Password and Confirm Password fields have no accessible label.
- An invalid phone number is shown only as "Please enter valid phone numbers".
